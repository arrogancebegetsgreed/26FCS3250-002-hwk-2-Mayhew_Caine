# Instructions: Part 1 

A new home security software project is being developed to support the door-to-door sales team. The team needs a system that can:

* List potential customers using publicly available data (e.g., number of rooms, presence of a garage).
* Help salespeople determine the most suitable security system for each customer using a questionnaire.
* Run on mobile devices with large screens.

Based on this description, create 10 high-level requirements for the sales system:

* 4 user functional requirements (what the system should do for users)
* 4 user non-functional requirements (how well the system should perform)
* 2 system requirements (technical or environmental constraints)

```
Write your requirements here!

User Functional Requirements:\
-Allow customers to complete questionnaires
-Allow salespeople to choose security system based off summarized questionnaire results
-Allow salespeople to save customers (consensually provided) info and contact info in a list
-Allow salespeople to view said list and export/use info for reports (or to create questionnaires?)

User Non-Functional Requirements:
-UI should be simple, so the process can be completed quickly and not require intensive training or certification
-Questionnaire's should be kept short and simple, and not require the customer to step away to obtain further information
-Customer support for the system should be available 24/7 (maybe with an AI assistant?) and should be easy to contact/use
-Screen should be easily readable in all environments and adjustment should be easy as well (with included accessibility options)

System Requirements:
- Run on mobile devices (phones, tablets etc) with larger screen sizes (the average tablet screen size is apparently 10-11 inches, so maybe like 8-9 specifically?)
- Run without a wi-fi connection (as the salespeople are going door to door, not contacting customer from one location with a stable wi-fi setup)
```
